## 五、模式小结（供后续任务立项参考）

1. **QML 路由预检 ↔ C++ 守卫口径一致性**（#1）：凡是「预检算容量、底层 API 带守卫」的组合，预检条件必须是底层守卫的**超集**同口径抄写；建议对铁砧/合成台/附魔台三处 QML 路由补源码钉探针（预检条件逐字断言），这类错位 C++ 矩阵全盲。
2. **帧驱动余量 vs 事件驱动沿**（#2）：所有「冷却/间隔」类门对「事件恰好等周期到达」的场景要做容差或改绝对时间戳；本作红石 10Hz、渲染 60fps 双时基并存，等周期边界（0.1s/0.2s）是最易踩的量化缝。
3. **有副作用的写操作触发同步信号处理器**（#3）：QML 属性变更 handler 是同步直连——任何「先写后读派生态」的顺序都要假设中间会插进 reroll/rev 自增；种子/快照类值应在第一次写之前取。
4. **文档化的恢复/降级路径要当代码维护**（#4/#10）：degrade lever 注释声称的操作步骤应被探针钉住（或干脆做成显式开关属性），否则第一次真正回退时才会发现路径已断。
