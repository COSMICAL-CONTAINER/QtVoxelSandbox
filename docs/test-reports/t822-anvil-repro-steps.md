## 0. 前置核对（防陈旧 exe / 旧存档 —— 必做）

本项目已出现 6 次「用户跑的是旧 exe、代码早已修复」的误报（t740/t744/t792/t772/t805/t814）。两条：

1. **版本戳**：启动游戏看**主菜单右下角小字**（形如 `2026-08-24 15:30 @ a1b2c3d`），或进存档按
   **F3** 看第二行 `build:`。哈希必须**等于或晚于** `fc8ec84`（`fix(t822)` 探针收口 commit）。
   不一致 = 陈旧 exe，重新 `cmake --build build` 后复测。
2. **旧存档警告（本轮新增嫌疑，重要）**：附魔的**存档持久化**是 08-16 的 t622 才落地的。在那之前
   保存过的世界里，附魔物品在存档里**本来就已是素品**（旧档 JSON 无 `enchants` 字段，读回静默降级
   为无附魔——兼容设计，不报错）。**请用本次新附魔的物品测**：若你观察的物品是几天前附魔、中间
   保存退出过的，请先确认它在背包里还有没有紫色光晕；没有光晕 = 存档里早就没了，与铁砧无关。

## 1. 防误判设计语义（先读，防把设计当缺陷）

| 现象 | 结论 |
| --- | --- |
| 合并两件各带「效率」和「时运」的工具，产物只有其中一条 | **设计**（同组互斥：效率/精准采集/时运三选一，t615 冲突组过滤；锐锋/亡灵/节肢同理三选一） |
| 已附魔的物品再放附魔台，三档不亮 / 点了没反应 | **设计**（一件物品只能进附魔台一次；MC 1.0 语义） |
| 附魔台三档全灰，放了工具也不亮 | **设计**（t795：须先在第二格放**青金石**，创造模式也要；高档须书架数达标） |
| 铁砧修复后产物耐久变了 | **设计**（修复 = 耐久回复；附魔不动） |
| 合并/修复消耗了 XP 等级 | **设计**（生存扣等级；创造免等级但材料照扣） |
| 改名产物名字 = 改名框内容，修复/合并产物名字 = 左槽原名 | **设计**（实例名随物品走，t622） |

## 2. 场景矩阵（每步都先看「预期」，不符才记为复现）

> 通用观察点（三层）：**紫色光晕**（槽位内物品的半透明紫叠层）、**tooltip 附魔行**（悬停显示
> 「效率 III」等）、**实际效果**（挖掘速度/攻击伤害）。

### 场景 1：单附魔工具 放入 → 取出（最简主干）

1. 附魔台：铁镐（或任意工具）+ 青金石 → 点一档 → 取出附魔镐入背包。
2. 确认：背包里该镐**有紫晕**；悬停 tooltip 显示附魔名 + 等级。若这里就没光晕 → 见「分层判别 A」。
3. 对铁砧右键开 UI → 左键点背包里的附魔镐（上光标）→ 点**左输入槽**放入。
- **预期**：左输入槽内物品**仍有紫晕**；悬停仍显示附魔行。放入的瞬间光晕消失 = 复现，记下并回报。
4. 左键再点左输入槽取回 → 点背包空位放下。
- **预期**：光晕、tooltip、挖掘加速全部保留。取出后变素品 = 复现，见「分层判别 C」。

### 场景 2：多附魔叠加（一次放满 4 条）

1. 附魔一把剑（或用铁砧把多本附魔书敲到同一把武器上）：目标凑 **锋利 + 击退 + 燃焰 + 耐久** 4 条。
2. 放入铁砧左槽 → 取出 → 再放入 → 再取出（两个来回）。
- **预期**：4 条附魔**全部**保留（tooltip 一次列出 4 行）。只丢其中部分（且不属于上表互斥组）= 复现。

### 场景 3：护甲放入（类别分支）

1. 附魔一件胸甲（保护 + 耐久）。
2. 放入铁砧左槽；再往**右槽**放铁锭做一次修复（耐久不满时才有修复选项）。
3. 取产物。
- **预期**：护甲附魔全程保留；修复只回复耐久。护甲类放入即丢附魔（工具正常）= 复现，注明「仅护甲」。

### 场景 4：附魔书合并（敲书）

1. 创造背包取一本附魔书（或附魔台给书附魔）。
2. Shift+左键把书从背包放进铁砧**右槽**；左槽放对应工具（如镐 + 效率书）。
3. 取产物。
- **预期**：工具获得书上附魔（同组冲突的条目会被过滤 —— 见第 1 节互斥表，属设计）。
   书本身消失（消耗 1 本）。

### 场景 5：存档读回后开铁砧（本轮最高嫌疑路径）

1. **本次新附魔**一把工具（不要用旧存档里的），放入背包。
2. ESC → **保存并退回到标题屏幕** → 重新进入同一世界。
3. 确认背包里该工具**仍有紫晕**（没有 → 见「分层判别 D」）。
4. 开铁砧 → 放入 → 取出。
- **预期**：与场景 1 相同，全程保留。**只有读档后才丢** = 存档序列化复现，见「分层判别 D」。

### 场景 6：连续操作（修复 → 合并 → 改名 一口气）

1. 两把同id磨损附魔镐：先 Shift 放入第一把（自动进左槽），再 Shift 放入第二把（自动进右槽）→
   合并 → 取产物。
2. 不关 UI，立刻把产物再放回左槽，改名框输入新名 → 取改名产物。
3. 不关 UI，再放一本附魔书敲第三段附魔 → 取产物。
- **预期**：三步产物分别保留附魔（合并 = 双方并集去冲突）、保留附魔 + 新名、追加书附魔。
   中间某步后附魔没了 = 复现，记下是第几步。

### 场景 7：铁砧开着时保存退出（中间态撞存档）

1. 把附魔物品放进铁砧左槽（**不取出**），UI 保持打开。
2. ESC → 保存并退出 → 重进世界。
- **预期**：物品**回到背包**且带附魔（关包自动归还 A/B 槽，t650；归还链带附魔，t550）。
   重进后物品消失 = 另一类缺陷；附魔消失 = 复现，见「分层判别 D」。

### 场景 8：丢弃 / 死亡复检（可选，实体链）

1. 手持附魔工具按 Q 丢弃 → 走过去拾回。
2. （生存）带着附魔工具致死 → 重生 → 回死亡点拾回。
- **预期**：两条路径拾回的物品附魔、耐久、名字全保留（t590/t622/t686）。

## 3. 分层判别（复现时按消失时间点定位，回报请带层号）

| 层 | 症状（附魔在哪一步消失） | 嫌疑代码段 |
| --- | --- | --- |
| A | 附魔台刚取出来就没光晕 | EnchantingTableUI.doEnchant 写入 / Hotbar::enchantSelected |
| B | 背包里一直有光晕，**一放进铁砧槽**就没（含 tooltip） | AnvilUI 本地槽 anvilEnch / AnvilSlot.hasEnch 绑定 |
| C | 铁砧槽里显示正常，**取出到光标/背包**后变素品 | held 光标序列（setHeldBlock→setHeldEnchants 顺序）/ takeProduct 产物路由 |
| D | 只有**保存退出再进**之后消失（当次会话内正常） | gatherPlayerState/applyPlayerState 序列化（或旧档数据 —— 见第 0 节第 2 条） |
| E | 特定物品类别（仅护甲 / 仅书 / 仅某工具）或特定附魔组合才丢 | 类别分支 / 冲突组过滤误伤 |

回报格式建议：层号 + 场景号 + 版本戳哈希 + 物品与附魔组合 +（可选）启动日志
（`[inv] setStack ...` 行能看到槽位 id/count/dur 变化）。
